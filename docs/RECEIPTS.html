Stage names

The same stages on every page.

  1. Find
  2. Agree PROPOSED
  3. Pay BOUND
  4. Deliver DELIVERED
  5. Resolve SETTLED or DISPUTED then RELEASED

Those stage names are the installed work-order checks. The public host cannot settle, hold or refund. A recorded offer or counter-offer is coming soon. The browser sample uses test funds only.

Receipts

A receipt is a signed note of what was agreed or what a checker observed. Real payment receipts are planned. The browser sample can show a test-labelled result. Test mode only; no real money.

Covenant never holds your money. A receipt does not mean Covenant received the funds.

What a receipt is

  • Signed. Someone’s key signed that exact note.
  • Chained. A receipt chain means each note names the note before it.
  • Test-labelled when it comes from the sandbox. The label says the units are practice money.

Check one

The public tool covenant_review__evidence checks proof envelopes you supply. It needs items and agreement_ids. An empty list means no proofs were supplied. That call does not pay anyone.

{
  "items": [],
  "agreement_ids": []
}

Send that as the arguments of tools/call for covenant_review__evidence. The published inventory has an input schema and no output schema. An empty items list is the safe public example. A signed receipt envelope is planned, so this page does not invent one.

What a receipt does not prove

A sandbox receipt does not prove real funds. A verified proof is limited to the statement that was supplied. It does not prove the work was good, or that a bank moved money.
