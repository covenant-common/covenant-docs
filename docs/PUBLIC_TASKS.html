  2. Agree PROPOSED
  3. Pay BOUND
  4. Deliver DELIVERED

Those stage names are the installed work-order checks. The public host cannot settle, hold or refund. A recorded offer or counter-offer is coming soon. The browser sample uses test funds only.

Review example

covenant_review__review takes a wrapped case. This is the public review reference’s empty case. Send it as the tool arguments. It is not a contract draft.

{
  "case": {
    "agreements": [],
    "bindings": [],
    "decisions": [],
    "evidence": [],
    "expected_heads": null,
    "grants": [],
    "group": null,
    "links": [],
    "notes": [],
    "obligations": [],
    "payments": [],
    "policies": [],
    "primary": null,
    "recoveries": [],
    "title": "Example only: no agreements or evidence supplied",
    "version": "covenant-coordination-case/0.1"
  }
}

Ask: “Draft proposed terms for a one-page source-linked research brief costing USD 25. When the 0.5% fee applies, you pay USD 25.13, the seller gets USD 25, and the fee is USD 0.13. With the fee left off, you pay USD 25, the seller gets USD 25, and the fee is USD 0. Buyer-example buys and supplier-example supplies. Delivery is within three business days after approval; the buyer reviews against the agreed scope. Leave it unsigned.” The agent can use covenant_contract__draft with explicit clauses, then return the result and any missing material details.

For a revised price, pass the exact original and proposed replacement bodies to covenant_contract__compare. Keep the original proposal intact. A change from USD 25 to USD 30 requires fresh approval. At USD 30, with the fee left off, you pay USD 30, the seller gets USD 30, and the fee is USD 0. When the 0.5% fee applies, you pay USD 30.15, the seller gets USD 30, and the fee is USD 0.15. A changed price is not an existing payment authorization.

For actual listing and deal records, follow the separate private account connection and owner approval steps. Do not send account tokens or signing material to the anonymous public endpoint.

When a public call will not do the requested job

A request to sign, publish an advert or send money cannot be completed by substituting a drafting or review call. Explain the required owner/account step and stop before claiming completion. General arithmetic, sentence edits and unrelated coding usually need no agreement tool.

The connection retains its existing identifiers, complete input schemas and annotations. Its legacy runtime identity is aap-public-directory, version 0.1; the public display name does not silently rename that identity. Discovery documentation explains the dated metadata and connection checks.

A repeatable check, with its limits visible

The frozen 20-prompt set contains nine direct requests, five indirect tasks and six negative controls. It includes synthetic attachment bodies, original tool identifiers and fixture hashes. Evaluators keep the expected choices separate from the prompts shown to a task agent.

The public execution harness has no model or API-key dependency. Its default command validates frozen inputs and replays explicitly synthetic response fixtures:

python3 tools/evaluate_public_tasks.py
python3 tools/evaluate_public_tasks.py --out /tmp/covenant-ato-offline-001

After reviewing the frozen execution profile, use the explicit live option to test the fixed anonymous endpoint:

python3 tools/evaluate_public_tasks.py --live --out /tmp/covenant-ato-live-001

The live path first initializes and compares the complete current inventory, protocol and legacy server identity with the retained snapshot. It then makes fourteen predetermined read-only calls. Six negative controls dispatch no tool. It refuses schema or metadata drift, credentials, redirects and oversized results; request waits, body size and the run have bounds. A transport/result error stops further calls without a retry or offline fallback. Existing output files are never overwritten.

The result format retains exact requests, responses, assertion results, call counts, live request times and text sizes; a viewable HTML companion summarizes them. The fixed new-draft examples check returned content and identifier format; they do not independently recompute those new identifiers. Offline placeholder identifiers are labelled synthetic and never treated as server observations.

Successful deterministic calls establish that the supplied cases execute and return expected fields. They do not measure whether an agent selected the tool unaided. Organic provider-store visibility, an explicitly selected connector's usefulness, offline catalogue choice and deterministic execution must be recorded separately. Model rankings, real-user retention, bookings and money movement remain unmeasured.

For weekly comparisons, retain this version's prompts and hashes, save each run separately and record changed model, client, plan, region, metadata or listing inventory. A changed prompt or oracle needs a new version. Metadata evaluation guidance recommends direct, indirect and negative tasks and one change at a time; plugin guidelines apply to descriptions.
