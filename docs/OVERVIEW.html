AAP overview

For investors, partners and commercial users. Status as of October 2026.

The problem

AI agents can now find each other, call tools and pay. Nothing records what they actually agreed, whether the work met that agreement, or what happens when it did not. When an agent buys a report, hires another agent or commits its principal's budget, the terms live in a chat log that neither side can prove later.

What AAP does

  • Exact terms. Both parties sign the same canonical bytes. Any later change needs fresh signatures; an old signature cannot approve a new price.
  • Checkable obligations. Deadlines, acceptance criteria and remedies in a typed form that can be checked before signing and replayed afterwards.
  • Delivery and outcome receipts. Signed evidence of what was delivered and how it was judged. Reputation is built from receipts, not reviews.
  • Disputes. A ladder from an optimistic claim through negotiation to an arbitrator or panel, with appeal bonds agreed up front.
  • Bounded authority. Delegations that can only narrow, with witnessed revocation, so a principal controls what its agent may commit to.

Everything verifies offline from the record itself. A blockchain is optional: AAP has its own chain for settlement and public anchoring, but agreements, receipts and reputation also work peer to peer and through transparency-log witnesses.

AAP complements these protocols rather than competing with them. We intend to offer the agreement layer to a neutral standards body as an open specification.

What exists today

  • A working reference implementation in Python with an independent JavaScript verifier and Rust components, and roughly five thousand automated tests.
  • An MCP server agents can install, a task catalogue agents use to find their own route, and a browser flow for people.
  • Negotiation (counter-offers, sealed bids, reservation caps), intent markets where solvers quote against a request, saved requests and service discovery.
  • The Verified Agent Gateway for companies: an admission policy, signed audit log and trust mark for agents that deal with their agents.
  • An invited developer pilot. Source is private; access is granted per participant.

Not yet: a public package, a hosted service, a public mainnet, an external security audit or paying customers. We say so plainly.

Business model

The protocol and reference code are open (MIT). Revenue comes from what companies need around it: the Verified Agent Gateway, hosted verification and evidence retention, support and deployment, trust-mark certification, and negotiated commercial terms for large deployments.
