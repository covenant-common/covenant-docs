Stage names

The same stages on every page.

  1. Find
  2. Agree PROPOSED
  3. Pay BOUND
  4. Deliver DELIVERED
  5. Resolve SETTLED or DISPUTED then RELEASED

Those stage names are the installed work-order checks. The public host cannot settle, hold or refund. A recorded offer or counter-offer is coming soon. The browser sample uses test funds only.

Money-path words

These are the words a first payment path uses. Each meaning is the one already written on the linked page. 25 USDC = 25,000,000 micro-units.

Access file

The private trial file. In the terminal client it is access.json. It contains the signing seed and the account token. The MCP configuration is a second file, mcp.json, and contains the bearer token only. Keep both outside an agent chat.

Bearer token

The account credential in the MCP configuration’s Authorization header. That file does not contain the signing seed. It is not itself an approval of a deal or a payment.

Agreement ID

The identifier of one exact agreement. Keep the expected agreement ID separately from any shortened summary. The source order and the final payment-enabled agreement have different IDs.

Request key

The retained key for one operation. A retry uses the identical operation, unchanged fields, and its original request key.

Successor bundle

For a marketplace successor agreement, the market package includes the original advert, order, fee disclosure and full payment requests. Approving the source does not approve the successor.

Leg give-0

The wallet-instruction example names the payment leg give-0 on an original source deal that uses Base or Ethereum USDC.

Sender and destination instruction

The seller uses destination. The payer uses sender. The instruction names a wallet. It alone does not authorize spending.

USDC_MICRO

Base and Ethereum USDC amounts on the payments page use six-decimal micro-units. 25 USDC = 25,000,000 micro-units. That is a token amount, not a dollar conversion.

transfer_terms

A field on the named asset in the USDC examples. Those examples show it as an empty object. Naming the asset does not, by itself, move the tokens.

Offer

A proposed set of terms: the work, the price, the deadline and how the result will be checked. Today an offer is a draft you send yourself, by email or chat. The public server does not deliver it and does not mark one draft as the open offer. A recorded offer is coming soon.

Counter-offer

A new draft that changes the other side’s terms, such as the price or the number of days. Today you write that new draft and swap it by hand. There is no counter-offer action on the public server. A recorded counter-offer is coming soon.

Fresh approval

After the terms change, everyone who must agree has to approve the new exact version. An earlier approval stays with the earlier version. The public comparison asks for this when the two copies differ, including when the only difference is the order of the same clauses.

Budget limit

A cap on what an agent may agree, such as up to £130. This cap is not available on the public tools or the hosted account tools. A budget limit is coming soon. The open server change is pull request 192. That link does not mean the pull request already adds amount caps.

Hold and release

In the browser sandbox, test money moves into a hold when the sample is funded, and the buyer releases it after delivery. Those are test units, not real USDC. On the hosted USDC route there is no hold. Payment is a direct transfer and it is final.

Resolver

A named third party in the local sandbox sample, used when a job is disputed there. The hosted USDC path does not require a resolver. A hosted dispute is a signed record between the buyer and the seller. The fee recipient is not required to co-sign that dispute.

MCP

The public tool connection. It can search and draft. It cannot sign, publish, pay or refund.

AAP

The engine name under Covenant. The native payment network is not live.

fee_opt_in

The payer’s choice to add a platform fee. The fee is not set yet, so this choice does not add an amount. The owner will confirm this.

Ed25519

The signature type used by the account tools.

supersedes

A link to the previous draft. A public draft refuses it. Each public draft stands alone.

eip155

A network id in the payment catalogue. Naming it does not move money.

escrow

The browser sample can hold test funds. Hosted USDC does not. That payment is final.

Trusted Surface

The page where you see the full price and approve with your passkey. An agent chat is not a Trusted Surface. Approval on this host is planned.

mandate

A signed limit on what your agent may do. AP2 v0.2 has a Checkout Mandate and a Payment Mandate. Each can be open (a limit before the exact cart exists) or closed (a yes to one exact checkout or amount). IntentMandate and CartMandate are previous names from AP2 v0.1. A mandate on this host is planned.

idempotency key

A caller-chosen key sent with a request. The same key and the same body are one operation. A repeat is planned to come back as idempotent_replayed. A different body with the same key is planned to come back as IDEMPOTENCY_CONFLICT. A request still running is planned to come back as IDEMPOTENCY_IN_FLIGHT. The public tools do not require this key today.

receipt chain

A series of signed receipts where each one names the receipt before it. A sandbox receipt is test-labelled. It does not prove real funds.

server card

A static JSON file that describes one remote MCP server. This docs site publishes a prepared copy. The API host path is not activated.

agent card

A static JSON file at /.well-known/agent-card.json that describes an A2A agent. This site does not publish one. That path is planned.

Web Bot Auth

A directory of signing keys a site publishes so a receiver can check that a bot’s HTTP request was signed by that bot. Cloudflare’s documentation is dated 8 October 2026. Covenant does not publish that directory. It is planned.

capture deadline

The last moment a held payment can be captured. After that moment, the planned path returns what is left. Not set yet. The owner will confirm this. No live rail has this deadline.

authorize

The step that reserves a payment without taking it yet. On a live card rail this is often called an authorisation. No hosted method can authorise a real payment today.

capture

The step that takes some or all of a payment that was held. A partial capture takes only the agreed part. Capture on this host is planned. The browser sample can release test funds. That is not a card capture.

void

Cancel a hold before any of it is captured, so the reserved amount is not taken. Void is planned. It is not a hosted refund of money already sent.

refund

Money sent back after it has been captured. The browser sample can return held test funds to the buyer. A hosted USDC transfer cannot be pulled back, and Covenant cannot refund it, because Covenant never holds your money.

reclaim

After the capture deadline, what was held and not captured comes back in the server sandbox. Not set yet. The owner will confirm this. No day count is set. The browser sample does not split a hold.
