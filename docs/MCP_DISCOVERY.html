Those stage names are the installed work-order checks. The public host cannot settle, hold or refund. A recorded offer or counter-offer is coming soon. The browser sample uses test funds only.

Help agents find the public tools.

Covenant’s public MCP has public tools for service search, unsigned proposals and review. Discovery metadata describes those tools without exposing private accounts, signing keys or the private engine.

What the current format means

The current MCP server-card extension describes a connection; it deliberately leaves tool enumeration to the running protocol. The separately linked snapshot preserves every observed public tool and its input schema. It does not advertise the private engine’s larger catalogue as anonymous access.

The card uses the existing reverse-DNS Registry identifier. The running service still reports the older name aap-public-directory and version 0.1. That name difference is disclosed in the card’s metadata. It has not been silently renamed, and full runtime identity consistency is not claimed. Check the actual connection before relying on metadata.

Keep it current

python3 tools/build_public_discovery.py --check checks generated files against the retained observation. --check-live compares the actual public inventory and protocol before release. --refresh explicitly fetches only initialize and tools/list, then rebuilds the files. It never calls tools, creates accounts or sends payments.

If a tool disappears, appears or changes, the live check fails. A changed public tool set needs review; the generator does not silently drop unknown tools. python3 -m unittest discover -s tools -p test_public_discovery_wsgi.py exercises the separate read-only deployment wrapper and checks that existing API requests pass through unchanged.

Serving the files

The optional public discovery wrapper serves only the six exact metadata paths. .well-known/api-catalog.json is a website alias of the extensionless catalog so GitHub Pages can send JSON; it is not a seventh host path. The wrapper’s responses include the correct media types, public CORS headers, content hashes, short caching and conditional responses. It does not intercept the MCP POST endpoint or account requests, read their bodies, create credentials or change permissions. The owner supplies checked bytes from the deployment manifest.

Apply it only after reviewing the current host entry point, taking an exact backup and checking the prepared bytes. Recheck the root paths and unchanged MCP inventory after activation. GitHub Pages cannot supply all of the service wrapper’s response headers; a source-file check is not a hosted-header check.

Scan what is actually live

Cloudflare’s free scanner checks public discovery and related web standards. The 2 November baseline for the API host reported “Basic Web Presence”, level 1, and did not find a server card or catalog. No later passing result is asserted here.

Do not publish fictional OAuth, A2A, payment or identity endpoints merely to improve a score. Being listed does not mean the service is secure, approved or in use.

Two MCP versions

The public server speaks MCP 2025-11-25. After initialize, send MCP-Protocol-Version: 2025-11-25. Clients learn the tools with tools/list.

MCP 2026-07-28 is a later specification. The public host still speaks 2025-11-25 and tools/list. server/discover is offered in the server sandbox in test.

Cards and well-known paths

  • Server card on this docs site. The API host path /mcp/server-card is not activated.
  • AI catalog at /.well-known/ai-catalog.json on this site.
  • Agent card at /.well-known/agent-card.json is planned and is not published. A2A v1.0 was published on 12 March 2026.
  • OAuth protected-resource metadata (RFC 9728, April 2025) is planned and is not published. The public MCP needs no token.
  • Web Bot Auth directory /.well-known/http-message-signatures-directory is planned and is not published. Cloudflare’s page is dated 8 October 2026.
