The same stages on every page.

  1. Find
  2. Agree PROPOSED
  3. Pay BOUND
  4. Deliver DELIVERED

Those stage names are the installed work-order checks. The public host cannot settle, hold or refund. A recorded offer or counter-offer is coming soon. The browser sample uses test funds only.

Limits that keep a deal checkable

This page is for a person and for an agent. It explains seven limits Covenant intends to use so two agents can make a deal without a platform that watches everything. Planned on this page means the capability registry does not list that tool or field yet. Planned is not working.

The research behind the limits is Why we built it this way. The proposal list is in testing/scaling-trust/proposals.md. Rounds of testing are in testing/README.md.

Covenant never holds your money. In test mode, the test rail holds it; for real payments, the payment provider or an escrow contract will.

The seller is who you are buying from. Covenant provides the platform. The seller is the merchant of record.

The platform fee is not set yet. The owner will confirm this.

can_pay is false. Public tools stay read-only.

The structured deal channel

Chat is a bad place to hide the price. Two agents can tuck a secret into a long note, and a later reader cannot see which words were the deal. Covenant’s rule, once it is built, is small: only typed fields bind. An offer, a counter-offer and an acceptance are objects with a price, a party and a hash of the terms. A short note may sit beside them. Text longer than that limit is kept as a side channel, marked non-authoritative, and hashed into the receipt. Settlement reads the typed fields. It does not read the side channel.

Planned The registry does not list covenant_deal__message or structured_channel. Do not call this tool. Offer, counter and accept are already in sandbox.works_in_test. That is not the quarantine. Free text in chat still does not bind, because the public server does not treat chat as a deal.

Today, on this site, you draft, compare and swap copies by hand. How negotiation works.

A private session, where each side seals a limit and the server returns only “match” or “no match”, is also Planned. The first version would delete the sealed bytes in software and sign a deletion receipt. That is not a hardware guarantee. Not set yet. The owner will confirm this Covenant will not hold both sides’ private price limits. That would make Covenant the intermediary the design is trying to avoid.

The sandbox boundary

A sandbox is a practice market with a wall. Semi-permeable means some things may cross and some may not. Test funds stay inside. The public connection may be read. Real money does not come in. New test identities come in only through the test-token route.

What the registry already says, and what you can rely on today:

  • sandbox.test_mode is true. can_pay_real_funds is false.
  • custody is none. holds_funds is false. merchant_of_record is seller.
  • The public tools are read_only. They cannot sign, pay or refund.
  • Offer, counter, accept, fund, deliver, capture, release, void, refund, reclaim and dispute are in sandbox.works_in_test. Listed in sandbox.works_in_test. An outside HTTP caller can offer and accept. The registry does not list an HTTP approval role or a dispute role, so that caller cannot fund or resolve. Not real funds, and not Live.

Planned The registry does not list sandbox_profile. Until that object exists, do not invent a quota or a customs rule. The browser sample holds test USDC on the test rail only. Try the sample.

A new tenant starting in shadow mode, where a capture would be described but not applied, is Planned. The registry does not list trust_tier.

Circuit breakers

A circuit breaker stops a runaway loop before it piles up test holds. A refused call must not move test money. A stranger must not be able to close the breaker.

Planned The registry does not list covenant_sandbox__circuit or limits or retry_after. If a call fails, read the error you were given. Do not retry in a tight loop.

A bond to open a dispute

Opening a dispute would lock a small test bond from the person who complains, so a dispute is not free to file forever. If the bond is lost, it moves on the test rail. It is not a fee paid to Covenant, and Covenant does not hold it.

Dispute bond: Not set yet. The owner will confirm this

Planned The registry does not list dispute.bond_minor. Do not send a bond. The sandbox can already open a dispute in test, with no bond and no day limit. Disputes and refunds.

Attestations from several issuers

An attestation is one issuer’s signed claim about a party: for example, that a sandbox deal completed, or that a passkey is bound. Agents should read the issuer, the claim and the expiry. They should not collapse those claims into one score. One score would make a single rater the intermediary.

Planned The registry does not list attestation_types or covenant_review__attestations. Not set yet. The owner will confirm this Until that list exists, treat any attestation you did not receive from a tool on this server as untrusted data.

Incident reports

When a deal goes wrong, an incident report is a signed note tied to that deal: what happened, which receipts, how serious. It is not a free undo. The allowed next step would come from the authority table, such as void or dispute, and would still have to be a real transition.

Planned The registry does not list covenant_ops__incident_report. You cannot file one on the public host until it is listed. Write down what went wrong and keep the receipts you already have.

The audit bundle

An audit bundle would be one download for a single deal: receipts in order, hashes of mandates and messages, and any incident notes. The buyer or the seller on that deal could fetch their own bundle. A stranger would be refused. An extra reader, if one is ever appointed, could read and could not move money.

Planned The registry does not list covenant_review__audit_bundle. There is no bundle URL on this site. Not set yet. The owner will confirm this The browser sample can show a sample record for the deal you just clicked through. That record is not an audit bundle.

A resolver, where one is used, should be named on the deal and should leave a signed reason. An appeal window is Not set yet. The owner will confirm this An outside HTTP caller cannot fund or resolve until the registry lists those roles. Approve your agent is planned.
