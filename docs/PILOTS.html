Try Covenant on one piece of work.

Covenant is the product built around the Agentic Agreements Protocol (AAP). We’re inviting developers, platforms and teams to test one useful workflow with us.

Email a private pilot outlineChoose a workflow

Email is the first step; you do not need a GitHub account. If you prefer a public discussion, you can use the optional GitHub pilot form. GitHub submissions are public, so include only information you are happy to publish.

Who is it for?

A likely first commercial user is a developer or platform building agent services and needing agreement infrastructure, integration and support. A good pilot also has people on both sides of the work and someone who can approve the result.

The free browser demo is hosted by the project maintainer under the jupitersstring GitHub account. It lets you play both sides of a sample deal. A pilot with your own agents is a separate, agreed piece of work.

Four places to start

Order a report through an agent service.

Agree the brief, budget, deadline and reviewer. Change the price, require the right approval, then follow a partial or complete delivery. The report buyer is the example end user; the service developer runs the infrastructure.

Manage a recurring service.

Set shared terms for regular work, then approve each job’s scope, price and deadline. Test whether both sides can see completed orders, milestones and remaining duties.

Share a content permission.

Record how someone may use material you control. With an agreed application connection, test whether the same permission and terms can be checked elsewhere.

Recover from an unclear handoff.

Exchange a work record, interrupt a connection and establish what happened before repeating an action. Start with sample files. Payment services, radios and physical devices each need their own setup and testing.

Agree the trial before it starts.

  1. Choose one task. Describe the current workflow and where people get stuck.
  2. Set the scope. Agree implementation access, integrations, deployment, duration, costs, responsibilities and who can pause the trial. Commercial use of covered core code needs a written licence; see proposed pricing.
  3. Define success. Record the baseline, ordinary job, changed terms, interrupted connection and disagreement to test. Agree what evidence to collect.
  4. Review the result. Compare outcomes, unresolved problems, support time and whether participants would use it again. Decide together whether to continue.

These are proposed trials, not reports of completed customer pilots. Begin with sample information. Real money, private records or outside actions require separately approved setup.

A short first message is enough.

Tell us the workflow owner, participants, task, current problem, tools to connect and one useful result. Leave out passwords, keys, customer records and confidential agreements. We can agree how to examine sensitive details later.

What we want to learn

  • Can both sides understand what they approved and what remains owed?
  • Can they finish the job and recover from a change, interruption or problem?
  • Does this reduce time spent clarifying or chasing work?
  • What does setup and support cost, and would the customer use it again?

Keep people in control.

Agree who can pause the trial. Stop and review if an approval is wrong, private information is shared incorrectly or nobody can establish what happened to an action or payment.

Early access. Covenant is not ready for production use; independent security review is still required. Access, test and backup environments, setup and commercial terms are agreed before a trial.
